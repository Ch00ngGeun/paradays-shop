1. 쇼핑몰 화면 구성
홈: 상품 이미지·상품명·가격을 카드 형태로 표시함. 상품 카드를 누르면 상세페이지로 이동함.
상단 메뉴: Home·Menu·Cart·Search로 구성됨. 좌상단에서 회원가입·로그인, 우상단에서 한국어·영어 전환이 가능함.
상품 상세: 상품 이미지·설명·가격·수량·사이즈를 확인하고 장바구니에 담는 화면임.
Cart: 담은 상품·수량·소계를 확인하고 결제를 시작하는 화면임.
로그인·회원가입: 계정 인증 및 가입 화면임. 로그인 후 마이페이지에서 프로필·주문 내역을 확인함.
관리자페이지: 관리자 권한 계정으로만 접근하는 쇼핑몰 운영 화면임.
2. Menu 사용 방법
Menu는 별도 카테고리 페이지가 아니라 홈 상품 목록의 필터임.

홈에서 Menu를 열고 Clothes·SkateBoard·Brand·SALE 등의 항목을 선택함.
선택한 조건에 맞는 상품 카드만 표시됨. 여러 조건 선택이 가능함.
All을 선택하면 전체 상품 보기로 돌아감. 필터 선택으로 별도 페이지·URL로 이동하지 않음.
데스크톱에서는 hover 또는 클릭으로 메뉴를 열고, 모바일에서는 터치로 열어 선택함. Search는 현재 화면 위에 검색 입력창만 열며, 검색 결과 연결은 아직 없음.

3. 상품 상세·장바구니 흐름
홈 상품 카드 선택 → 상품 상세 → 수량·사이즈 선택 → 가격 옆 ＋ → 담기 안내 → Cart 이동 또는 계속 쇼핑 순서임.

기본 상품 상세 경로는 /products/{slug}, 관리자 발행 상품은 /products?slug={slug}임.
재고가 0인 상품은 장바구니 담기가 차단됨.
상단 Cart를 누르면 /cart로 이동함. 상품 수량 변경·삭제·소계 확인이 가능함.
장바구니는 해당 브라우저에 저장됨. 다른 기기·브라우저와 자동 공유되는 서버 장바구니는 아님.
로그인·약관 동의 후 CHECK OUT을 누르면 Toss 결제창을 여는 흐름임. 비로그인은 로그인 안내가 표시됨.
결제 결과는 /cart에서 처리함. 별도 결제완료 페이지는 없음. 실제 결제 검증은 별도임.
판매자 요청 입력란은 주문 저장에 연결되지 않았고, 배송지 입력 화면도 없음.
4. 로그인·회원가입·마이페이지
회원가입: 좌상단 회원가입 → /signup → 이메일·비밀번호·필수 동의 → 인증 → 가입 확인 순서임. 인증 방식은 서비스 설정에 따라 달라짐.
로그인: 좌상단 로그인 → /login → 이메일·비밀번호 입력 → 로그인 → 이전 화면으로 복귀함. 복귀 경로가 없으면 홈으로 이동함.
비밀번호 복구: 로그인 화면의 계정 복구 → 이메일 입력 → 인증 코드·새 비밀번호 입력 → 완료 안내 순서임.
마이페이지: 로그인 후 좌상단 마이페이지 → /account → 프로필·주문 내역 확인 → 이름·전화번호·마케팅 동의 수정 및 저장이 가능함.
Cart에서 로그인한 경우 Cart로 복귀한 뒤 결제 버튼을 다시 눌러야 함.
5. 관리자 전용 쇼핑몰 관리 화면
관리자 기능은 /admin 내부 메뉴로 구성됨. 메뉴마다 별도 페이지로 이동하는 구조는 아님.

관리 메뉴	사용 목적
운영 현황	쇼핑몰 운영 지표 확인용임.
상품 등록	상품명·브랜드·가격·옵션·설명·이미지·공개 여부 입력 및 저장용임.
재고 수정	상품별 재고 확인·수정 및 상품 관리용임.
브랜드	브랜드 정보 관리용임.
회원	회원 목록·정보 및 권한 관리용임.
쿠폰	쿠폰 초안 저장용임. 실제 주문 할인 적용 완료와 구분함.
마케팅	캠페인 초안 저장용임. 실제 메시지 발송 완료와 구분함.
입고 OCR	이미지에서 상품 정보를 인식한 뒤 검토·수정·저장하는 화면임.
상품 등록은 입력 → 공개 여부 선택 → 저장 → 공개 상품의 홈 노출 순서임. 실제 저장·조회는 서버 연결과 관리자 권한이 필요함. 연결 없는 임시 초안은 영구 저장으로 취급하지 않음.

입고 OCR은 이미지 선택 → OCR 인식 → 원문·상품명·브랜드·옵션·수량 검토 및 수정 → 검토 초안 저장 순서임. OCR 저장만으로 상품 생성·재고 반영이 이루어지지 않음. 로컬 OCR 검토본은 서버 재시작 시 삭제됨. 운영 OCR 사용 가능 여부는 별도 검증이 필요함.

6. 관리자 진입 방법
쇼핑몰 좌상단 로그인을 눌러 /login으로 이동함.
관리자 권한이 부여된 계정으로 로그인함.
로그인 후 쇼핑몰 좌상단의 마이페이지 / 사용자명 / 관리자페이지 중 관리자페이지를 누름.
/admin에서 운영 메뉴를 선택해 관리함. 관리자 화면에서는 쇼핑몰용 상단 헤더가 표시되지 않음.
관리자페이지 링크는 로그인된 계정에 admin 그룹 권한이 있을 때만 표시됨. 로그인만으로 모든 계정에 표시되지 않음.
링크가 없으면 관리자 권한과 로그인 상태 확인이 필요함. 권한 변경 후에는 재로그인이 필요할 수 있음.
/admin 직접 접속도 가능하지만 동일한 권한 검사를 거침. 비로그인은 로그인 안내, 비관리자는 접근 제한 안내가 표시됨.
7. 사용자 지정 테스트 예정 계정

사용자가 지정한 테스트 예정 계정임. 실제 계정 등록·관리자 권한 부여·로그인 성공 여부는 별도 확인 대상임. 이번 문서 작업에서는 계정 생성·비밀번호 변경·권한 부여·로그인 테스트를 수행하지 않음.

# PARADAYS storefront prototype

Next.js App Router + TypeScript strict 기반 스케이트보드샵 구현물임. 정적 스토어프론트와 AWS CDK 기반 Cognito·주문·Toss Payments 백엔드 소스까지 구현되어 있음. AWS 배포, Toss 키 입력, 실제 승인·웹훅 호출은 아직 실행하지 않았음.

## Run locally

```bash
npm install
npm run dev
```

파일 감시 한도가 낮은 환경에서 `EMFILE`이 발생하면 아래 방식으로 개발 서버 실행하면 됨.

```bash
WATCHPACK_POLLING=true npm run dev -- --webpack --port 3010
```

품질 확인 명령:

```bash
npm run lint
npm run typecheck
npm run format:check
npm run test
npm run build
```

Playwright 브라우저가 설치되지 않은 환경에서는 한 번만 아래 명령 실행 후 E2E 테스트 실행하면 됨.

```bash
npx playwright install chromium
npm run test:e2e
```

## Commerce implementation status

- 승인된 로고 수령 후 `public/brand/paradays-logo-placeholder.svg`를 실제 로고 파일로 교체하고 파일명·`components/logo-placeholder.tsx` 경로를 함께 확인하면 됨.
- 상품 이미지는 `public/images/product-placeholder.svg` 대신 CMS 또는 승인된 제품 촬영본으로 교체하면 됨.
- `infra/`에는 Cognito Hosted UI + PKCE, 회원 프로필·주문 API, 서버 가격 검증, Toss V2 승인·웹훅 재조회, 관리자 전체 환불 API가 포함됨.
- 실제 결제 전에는 AWS 환경 배포, Toss client/server key 등록, callback/CORS 도메인 제한, 테스트 승인·웹훅 검증이 필요함. 상세 절차는 [`infra/README.md`](./infra/README.md) 참고하면 됨.
